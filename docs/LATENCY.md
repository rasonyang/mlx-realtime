# mlx-realtime — Latency report

> **Status: template (M6, 2026-10-23).** No real numbers yet: the real stack runs once M0's GPU work
> is done. The only run below is on the **mock stack** (mock LLM, ASR and TTS), a format example
> whose numbers mean nothing about the service.

This report answers two questions on the real stack: how long a caller waits after they stop
speaking, stage by stage; and how accurately their speech is transcribed. It is generated by
`bench/bench.py`, which talks to `/v1/realtime` exactly as a telephone client does.

## 1. How the numbers are produced

**Input.** `spikes/data/manifest.jsonl`: the 126 public M0 utterances (FLEURS zh and en, ASCEND
code-switched; `spikes/data/README.md`), 42 per set, 25 with numbers. Each row has three copies;
`--variant` picks one:

| Variant | Audio | Sent as |
|---|---|---|
| `tel8k` (default) | the 8 kHz G.711 stream (μ-law or A-law), the telephone channel | decoded, resampled to 24 kHz `audio/pcm`; with `--codec pcmu`/`pcma` (from M7) the original G.711 bytes |
| `tel16k` | the same telephone copy, back at 16 kHz | resampled to 24 kHz |
| `wide` | the 16 kHz wideband copy | resampled to 24 kHz |

Any other manifest (`audio`, `text` per row) or a directory of WAVs with a `.txt` transcript beside
each also works; a WAV may be any PCM16 rate (8 kHz included). `--sets`, `--ids` (a regular
expression), `--numbers include|exclude|only` and `--limit` select a subset.

**Replay.** One session per worker (`--concurrency N` workers in parallel, a new session every
`--turns-per-session` utterances), configured as AICC configures it: `server_vad` with
`silence_duration_ms` 500, `create_response: true`, transcription on. Each utterance is sent in
20 ms `input_audio_buffer.append` frames at real-time speed, then silence frames, without a break,
until the turn is answered (every committed item transcribed, every response done, then 300 ms) or
given up (no turn detected after 6 s of silence; 60 s in all). The line never goes quiet, as on a
call; the client plays nothing, so there is no echo.

**Per utterance.**

- *Client end to end*: from the moment the client sent the end of the speech to the first
  `response.output_audio.delta` of the response that answered it. The end of the speech is the
  last 20 ms frame within 35 dB of the loudest and above −50 dBFS; this energy estimate usually
  lies later than Silero's, so the client figure tends to be lower than the server's.
- *Server stages*, from `GET /debug/turns?session_id=…` (the gateway must run with
  `observability.debug_endpoints: true`): each stage named after the mark that ends it
  (ARCHITECTURE §9), and the server's end to end, `first_audio_sent − speech_end`.
- *Transcript*: `conversation.item.input_audio_transcription.completed` (concatenated when the VAD
  cut the utterance into several turns; the report counts those).

| Stage | From → to | What it measures |
|---|---|---|
| `speech_stopped` | `speech_end` → `speech_stopped` | the VAD's end-of-speech decision: `silence_duration_ms` plus detection |
| `turn_confirmed` | `speech_stopped` → `turn_confirmed` | Smart Turn's verdict (0 when silence alone ends the turn) |
| `asr_done` | `turn_confirmed` (or `committed`) → `asr_done` | the ASR request |
| `llm_first_token` | the later of `asr_done` and `response_created` → `llm_first_token` | the LLM's time to first token |
| `first_sentence_ready` | `llm_first_token` → `first_sentence_ready` | the segmenter waiting for the first sentence |
| `tts_first_chunk` | `first_sentence_ready` → `tts_first_chunk` | the TTS queue wait and time to first chunk |
| `first_audio_sent` | `tts_first_chunk` → `first_audio_sent` | trimming, encoding and the first delta's emission |

**Report.** Per-stage and end-to-end P50/P95 (linear interpolation), and ASR error rates pooled
over each set with M0's `text_norm` rule (`bench/scoring.py`, as S4 scored): CER for `zh`, WER for
`en`, MER (one token per CJK character, one per Latin word) for `mix` and for all rows together.
Rows with numbers are reported apart, because references keep digits that speakers say as words.
`report.json` keeps every turn; `report.md` holds the tables below.

The same numbers are on `/metrics` while the service runs: `mlxrt_stage_seconds{stage}`,
`mlxrt_e2e_seconds`, and the windowed `mlxrt_stage_p50_seconds` / `mlxrt_stage_p95_seconds` over
the last `observability.quantile_window_turns` turns.

## 2. Generating the report

The real stack (once the orchestrator releases the GPU):

```sh
MLXRT__OBSERVABILITY__DEBUG_ENDPOINTS=true make dev        # terminal 1: backends and gateway
uv run --locked python -m bench.bench \
    --url ws://127.0.0.1:8000/v1/realtime \
    --input spikes/data/manifest.jsonl --variant tel8k \
    --concurrency 1 --out bench/results/real-tel8k            # terminal 2
```

Then the same with `--variant wide` (the channel's cost), and with `--concurrency 2` and `4`
(contention on the serialized TTS). `make bench BENCH_ARGS="…"` runs the same command;
`bench/results/` is git-ignored. Copy each `report.md` into §3 with its date, commit, machine and
power mode (M0 measured Low Power Mode as about 0.6× under sustained load).

The mock stack, no backends (the gateway runs in-process with `--serve`):

```sh
uv run --locked python -m bench.bench --serve config.mock.yaml --ids '_00[1-4]$' \
    --turns-per-session 1 --concurrency 2 --out bench/results/mock-example
```

Several sessions share the one serialized TTS stream; how that affects the delta gaps and first
audio, before and after M6's audio reserve and EDF queue, is measured in PROGRESS.md (M6,
"Fairness, before and after") and reproduced with `make fairness`.

### Mock stack (format example only)

**These numbers describe mock providers, not the service.** The mock ASR returns one fixed
sentence for every utterance (so the error rates are meaningless), the mock LLM echoes it with
50 ms to the first token and 20 ms per token, and the mock TTS speaks a sine tone. Only the VAD
(Silero, real) and the gateway's own work are real.

Generated on 2026-10-23 (commit 73bf8bb plus the M6 working tree) with:

```sh
uv run --locked python -m bench.bench --serve config.mock.yaml --ids '_00[1-4]$' \
    --turns-per-session 1 --concurrency 2 --out bench/results/mock-example
```

Read it as a format check: `speech_stopped` ≈ 520 ms is the 500 ms `silence_duration_ms` plus
Silero's frame; `asr_done`, `llm_first_token` and `tts_first_chunk` are the mocks' 50 ms delays;
`first_sentence_ready` ≈ 270 ms is the segmenter waiting for the mock's 20 ms-per-character echo to
reach the first sentence end. One session per utterance avoids a mock artifact: with the same fixed
transcript every turn, the next turn matches the previous answer and echo-turn suppression (D17)
drops it.
