## How the utterances were chosen

Every step is deterministic. Re-running the commands below reproduces the same files, which are
checked by sha256.

**Common rules.** 42 utterances per set, 1–10 s. Equal-share length bins, with a bin's deficit
redistributed to the others. Up to 12 number-bearing utterances per set are taken first. The rest
alternate between groups (gender for FLEURS, speaker for ASCEND).

**FLEURS (zh, en): read speech.**

- A `test.tar.gz` is 525 MB (zh) or 290 MB (en), and the parquet copies are single row groups of
  696/402 MB, which the Hub's dataset viewer cannot serve per row. Downloading a whole split was
  ruled out because the link is slow and shared.
- The archive stores its members sorted by file name, and the names are random 64-bit ids. So the
  first K = 140 members are a random sample, and a prefix of the gzip stream can be decoded on its
  own.
- The script selects from those 140 members using the TSV metadata, then streams the archive only
  up to the last selected member. That is 73.6 MB of 525 MB for zh (137 of 945 members), and 57.2 MB
  of 290 MB for en (135 of 647 members). Member order and `num_samples` are verified while streaming.
- One recording per sentence. Numbers here means digits in the raw transcription.
- FLEURS has no clips shorter than 3.6 s. Short utterances come from ASCEND.

**ASCEND (mix): spontaneous code-switched conversation, Hong Kong speakers.**

- Only parquet row groups 4, 9 and 11 are read (about 23 MB of audio, instead of the 106 MB test
  file). Rows are ordered by session and speaker; these three groups cover both test speakers
  (spk3, spk17) and all four test sessions.
- Rows are kept when `language = mixed`, they have no `[UNK]`, they contain at least one CJK
  character and one non-filler English word, and they have at least 4 tokens. Duplicate texts are
  dropped.
- Numbers here means the `has_number` heuristic below.
- Caveat: the ASCEND test split has only these two speakers.

## Level

The sources differ by about 50 dB. The median active speech level is −40 dBov for FLEURS zh, −61 dBov
for FLEURS en (down to −68), and −22 dBov for ASCEND, whose loudest files reach 0 dBFS. Feeding such
levels into G.711 would measure the codec's low-level noise, or clipping, instead of a telephone
channel.

- Each utterance therefore gets **one gain**, applied to the original samples (float) before PCM16
  conversion. The gain brings the active speech level to **−26 dBov**, unless that would put the
  peak above −1 dBFS. −26 dBov is the nominal level used in ITU-T speech and codec tests.
- The level is measured with ITU-T P.56 method B: a numpy port of the G.191 `sv56` algorithm,
  `p56_active_level` in the script. It reads −22.98 dBov on a continuous −23.01 dBov sine.
- Both the 16 kHz and the telephone copies carry this gain, so comparing them isolates the
  telephone channel.
- Two zh utterances are peak-limited, at −29.1 and −27.3 dBov. All others are within 0.5 dB of −26.
- The rows record `gain_db`, `source_active_level_dbov` and `active_level_dbov`. The untouched
  originals stay in `raw/`.

## Telephone copies

```
16 kHz PCM16 (level-normalized) --soxr.resample(16000->8000, quality="HQ")--> round/clip to int16
  --G.711 encode (mu-law; A-law for every 3rd utterance of each set: ids _003, _006, ...)-->  asr/tel8k/<id>.ulaw|.alaw
  --G.711 decode--> --soxr.resample(8000->16000, "HQ")--> round/clip to int16 --> asr/tel16k/<id>.wav
```

- G.711 uses Python 3.12's stdlib `audioop` (`lin2ulaw`/`ulaw2lin`, `lin2alaw`/`alaw2lin`, width 2).
  `audioop` is deprecated since 3.11 (PEP 594) and removed in 3.13, which is why this project pins
  `requires-python = ">=3.12,<3.13"`. The gateway will use its own lookup tables (S7 checks them
  against `audioop`).
- Band-limiting comes only from the 8 kHz resampler (flat to about 3.4 kHz; −5.7 dB at 3.8 kHz;
  nothing above 4 kHz). No 300–3400 Hz (G.712) channel filter is applied, and the chain adds no gain
  of its own.
- Sanity check on a 1 kHz sine at −20 dBFS peak (−23 dBov): the round-trip SNR is 36.6 dB (μ-law)
  and 36.0 dB (A-law).
- No clipping occurred anywhere (`clipped_samples` in each row).

## Manifest fields (`manifest.jsonl`)

| Field | Meaning |
|---|---|
| `id` | `<set>_<nnn>`, numbered by increasing duration within the set |
| `set` | `zh`, `en` or `mix` |
| `path_16k`, `path_tel_16k` | wideband and telephone WAVs (16 kHz mono PCM16) |
| `path_8k_ulaw` or `path_8k_alaw`, `codec_8k` | the G.711 byte stream and its law (`ulaw` or `alaw`) |
| `duration_s` | duration of the 16 kHz copy |
| `text` | original reference: FLEURS `raw_transcription`, ASCEND `transcription` |
| `text_norm` | scoring reference (rule below) |
| `has_number` | heuristic flag: digits; Chinese numerals in number patterns (e.g. 六月, 一百, 七八十位); English number, month or currency words |
| `source`, `source_repo`, `source_config`, `split`, `revision`, `license`, `url` | provenance |
| `source_id` | FLEURS file name, or ASCEND row id |
| `source_ref` | FLEURS sentence id, or ASCEND original wav name |
| `speaker` | FLEURS gender, or ASCEND `spk<id>/ses<session>` |
| `active_level_dbov` | P.56 active speech level of the 16 kHz copy (target −26) |
| `rms_dbfs`, `peak_dbfs` | whole-file RMS (silences included) and peak of the 16 kHz copy |
| `gain_db`, `peak_limited` | gain applied to the source, and whether the −1 dBFS peak limit set it |
| `source_active_level_dbov`, `source_activity` | P.56 level and activity factor of the original |
| `clipped_samples` | samples clipped at each int16 conversion (all 0) |
| `sha256_16k`, `sha256_source` | checksums of the 16 kHz copy and of the downloaded original |

**`text_norm` rule (for CER/WER/MER).**

1. Apply Unicode NFKC, which turns full-width forms into half-width ones. Map `’` and `‘` to `'`.
2. Lower-case.
3. Replace every punctuation (P\*) or symbol (S\*) character with a space, except an apostrophe
   between two letters (`what's` stays).
4. Collapse whitespace. Remove whitespace next to a CJK character, and keep single spaces between
   Latin and digit tokens.

Examples: `1990 年，由于…` → `1990年由于…`; `one-hundred percent` → `one hundred percent`;
`（Recep Tayyip Erdoğan）` → `recep tayyip erdoğan`.

Scoring caveats:

- Numbers are **not** verbalized. FLEURS zh writes `1990 年`, while speakers say 一九九零年. Score
  `has_number` rows separately, or apply inverse text normalization.
- ASCEND references keep fillers (呃, 嗯, um, uh) and letter-by-letter spellings (`i s m`).
- Suggested tokenization for the mixed error rate: one token per CJK character, one per Latin word.

## Echo material (S11)

**ITU-T G.168 echo path models** (`echo/g168_paths.json`).

- Source: G.168 (04/2015), edition 8.0, Annex D, "Echo-path models for testing of speech echo
  cancellers". There are 8 sequences m1–m8 at 8 kHz:
  - m1–m4: network hybrid simulator, clause D.2, Tables D.2–D.5.
  - m5–m8: measured in North American networks, clause D.3, Tables D.6–D.9.
  - Clause D.4 says the paths measured in France match m1, m5 and m6, and adds no tables.
- Lengths: m1 64 taps (8 ms); m2, m3, m5, m7 96 (12 ms); m8 99 (12.4 ms); m6 120 (15 ms); m4 128
  (16 ms).
- Use (Eq. D-1): `g(k) = 10^(-ERL/20) · K_i · m_i(k − δ)`.
  - `K_i` comes from Table D.1a for CSS or speech-like input, or Table D.1b for tones.
  - The minimum ERL is 6 dB, except m2 at 6.55 dB, m7 at 11.06 dB and m8 at 9.27 dB with the D.1a
    factors.
  - δ is the bulk delay. S11 plans 20–300 ms, and ERL 6–20 dB.
- Extraction: pdfplumber word coordinates, with tables read in columns as the Recommendation
  specifies. The checks below all passed:
  - `K_tone = 1/max|M_i(f)|` (8192-point DFT, Eq. D-2/D-3), recomputed for all 8 models, matches
    Table D.1b to 3 significant digits.
  - The D.1a/D.1b values parsed from the text equal the transcribed constants.
  - The coefficients are identical in the G.168 (2015) Cor. 1 (12/2022) reprint, which is in force
    and only corrects a reference.
  - They are identical to an independent `pdftotext -layout` parse.

**Microsoft AEC Challenge subset** (`echo/aec_challenge/`): acoustic echo, not line echo.

- 20 examples from the synthetic set's `test` portion, all without added noise: 10 with linear
  far-end and 10 with nonlinear (distorted) far-end, evenly spaced over the signal-to-echo ratio
  (−10…+9 dB).
- Each example has 4 files, 10 s each at 16 kHz mono PCM16: `farend_speech`, `echo_signal`,
  `nearend_speech` and `nearend_mic_signal`. Speech is LibriVox English.
- Each file is checked against its git-LFS pointer (sha256 and size). `subset.json` records the
  `meta.csv` rows.

**Far-end and near-end speech** for the S11 line-echo simulation comes from the manifest itself:
the zh, en and mix sets. No separate noise corpus was fetched. S11 can synthesize noise, or add a
permissive corpus later, such as DEMAND (CC-BY-SA-3.0) or MUSAN (mostly CC-BY-4.0).

## Regenerate

From the repository root:

```sh
cd spikes/datasets
uv sync --locked
uv run --locked python -I a2_data.py fleurs  --data ../data      # FLEURS TSVs + archive prefixes (~130 MB)
uv run --locked python -I a2_data.py ascend  --data ../data      # ASCEND row groups 4, 9, 11 (~23 MB)
uv run --locked python -I a2_data.py build   --data ../data      # 16 kHz + telephone copies, manifest
uv run --locked python -I a2_data.py g168    --data ../data      # ITU PDFs (6.7 MB) -> echo/g168_paths.json
uv run --locked python -I a2_data.py aec     --data ../data      # AEC Challenge subset (~26 MB)
uv run --locked python -I a2_data.py summary --data ../data --results ../results
```

- `fleurs` and `ascend` skip work whose `selection.json` exists; pass `--force` to redo it.
- `build` rewrites `asr/` from `raw/`.
- `summary` writes `spikes/results/a2_datasets.json`, copies `manifest.jsonl` to
  `spikes/datasets/`, and copies this file to `spikes/data/README.md`.
- Hugging Face downloads use `HF_TOKEN` if it is set; all sources are public.
